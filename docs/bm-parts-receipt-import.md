# Бус Маркет S: імпорт накладних

Підключення: **Налаштування → Інтеграції → Бус Маркет S**. Ввести API-ключ,
перевірити підключення, вибрати існуючого постачальника CRM і зберегти налаштування.
Ключ зберігається через наявний зашифрований vault, не в коді чи журналі.

**Надходження → Завантажити накладні** запускає окреме фонове завдання для кожної
підключеної інтеграції з можливістю `supplier.receipts` (Укркар і Бус Маркет S).
Період — сьогодні та попередні 13 календарних дат за Europe/Kyiv; він фіксується
для всіх постачальників при натисканні. Статус і кількість документів показуються
окремо для кожного постачальника. Збій одного підключення не скасовує завдання інших.

## API

Офіційні джерела:
- https://developer.bm.parts/api-docs
- https://developer.bm.parts/tutorials/sales-with-products
- https://developer.bm.parts/tutorials/date-filters
- https://developer.bm.parts/tutorials/pagination

Використовується лише `GET https://api.bm.parts/documents/sales_with_products`:
`period={YYYY-MM-DD,YYYY-MM-DD}`, `direction=asc`, `edo_signed=all`, `per_page=30`.
Ключ передається в `Authorization` без Bearer, з обов'язковим User-Agent.
Постачальник фільтрує ISO календарні дати документів; дата накладної береться
з `created_at`. Оплати, заявки, повернення та інші типи документів цей метод не повертає.

Сторінки читаються до `documents: []` або документованого `documents: null`.
Коротка сторінка сама по собі не означає кінець списку. Повтор сторінки,
невідомий формат, помилка авторизації, вихід за період або ліміти не вважаються успіхом.
Ліміти: 100 сторінок, 7 хвилин на завдання, 25 секунд на HTTP-запит,
5 MB на відповідь, 200 позицій на накладну. Перенаправлення заборонені.

## Дані й дублікати

- Створюються лише чернетки; склад, каталог і взаєморозрахунки не змінюються.
- `number` — унікальний номер у межах організації. Ручні документи з таким номером
  пропускаються незалежно від дати. Інший постачальник із таким номером — конфлікт.
- `document_uuid` зберігається як зовнішній ID, джерело — `bm-parts`.
- Валюта `UAH` / `ГРН` / `грн` зберігається як UAH. Інші валюти відхиляються.
- Перевіряються точні кількість × ціна, суми рядків і загальна сума.
- Назва — `name_for_invoice`, потім `name`, потім виробник + артикул.
- Зіставлення товарів використовує існуючі правила за виробником, артикулом та одиницею.
- Номер імпортованої накладної не редагується, щоб повторний імпорт не створив дубль.
- Документ і зв'язок інтеграції записуються однією транзакцією. Повторний запуск і
  повторні спроби враховують уже створені документи.

Міграцій бази цей PR не потребує; використовує схему імпорту Укркар з v1.1.29.
Локальний `npm run dev:ukrcar-worker` тепер обробляє вручну запущені завдання обох
постачальників і досі вимагає локальну базу та `DISABLE_BACKGROUND_JOBS=1`.

Тести: адаптер/пагінація/суми/помилки API, запуск кількох інтеграцій, ізоляція
помилок, пропуск ручних документів, відновлення завдання, конкурентні імпорти,
атомарність, ізоляція організацій і незмінність складських/фінансових записів.
