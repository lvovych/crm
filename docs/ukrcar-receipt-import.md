# Імпорт накладних Укркар

На сторінці **Надходження** кнопка **Завантажити накладні** ставить завдання
`supplier.receipts.import` в наявну чергу `IntegrationJob`. Обробник інтеграцій
запускається щохвилини. Завдання продовжується після закриття сторінки;
повторне відкриття показує його стан. Потрібні права читання і створення надходжень.

## Підключення

1. У **Налаштування → Інтеграції → Укркар** ввести логін і пароль кабінету.
2. Після успішної перевірки вибрати наявного постачальника CRM та зберегти налаштування.
3. На сторінці надходжень натиснути **Завантажити накладні**.

Логін і пароль зберігаються через наявний AES-GCM vault. Ключ задається через
`INTEGRATIONS_ENCRYPTION_KEY`. Cookies сесії живуть лише протягом одного запуску.
Паролі, cookies, HTML кабінету та бекапи не потрапляють до Git або журналу інтеграції.

## Правила

- Період: сьогодні та 13 попередніх календарних дат за `Europe/Kyiv`.
  Межі фіксуються при постановці завдання, включно для повторних спроб.
- Читаються всі сторінки взаєморозрахунків і деталі лише нових накладних
  `Реализация товаров`. Оплати й повернення пропускаються.
- Номер накладної — наприклад, `9000388299` — унікальний **у межах організації**,
  незалежно від дати і постачальника. Це гарантує унікальний індекс PostgreSQL.
  ID сторінки Укркар зберігається окремо, а не використовується замість номера.
- Наявні документи, включно з ручними та скасованими, не перезаписуються.
  Збіг номера в іншого постачальника — конфлікт для перевірки.
  Номер уже імпортованого документа не можна змінити під час редагування.
- Кожна нова накладна і її зв'язок із джерелом створюються атомарно як чернетка.
  Складські залишки, каталог товарів і взаєморозрахунки не змінюються.
- Картка товару зіставляється лише за однозначним збігом виробника, артикула
  та одиниці виміру. Невідомі товари зберігаються без `partId` для ручного зіставлення.
  Виробник зберігається також у `brandSnapshot`.
- Укркар іноді не передає назву товару: тоді використовується виробник + артикул.
  Ціни, кількість, рядкові суми й загальна сума перевіряються точно, без float-арифметики.
- Помилка одного документа не заважає завантажити інші. Черга повторює невдалі
  завдання до трьох спроб із наявною затримкою. Збережені чернетки не дублюються.
- Конкурентні натискання об'єднуються під транзакційним блокуванням у базі;
  вже запущене або відкладене завдання повторно не створюється.
- Ліміти: 100 сторінок, 200 рядків у документі, обмежений час запиту й обробки.
  Неочікувані сторінки/авторизація/суми завершуються явною помилкою, а не успішним
  результатом «0 документів». Перенаправлення на сторонні домени заборонено.

## Міграція

`20261119093000_ukrcar_receipt_import` замінює унікальність за
організацією/постачальником/номером/датою на організацію/номер.
Перед застосуванням перевірити:

```sql
SELECT "organizationId", number, count(*)
FROM supplier_receipts
GROUP BY "organizationId", number HAVING count(*) > 1;
```

За наявності конфліктів міграція зупиняється без автоматичного видалення документів.

## Локальна розробка на копії бази

Використовувати окрему базу, прив'язану лише до loopback-інтерфейсу.
`DATABASE_URL` має вказувати на цю базу, а `NEXT_PUBLIC_APP_URL` — на локальний сайт.
Секрети авторизації та шифрування для локального середовища мають бути окремими.

Після відновлення бекапа тримати `DISABLE_BACKGROUND_JOBS=1`, щоб не запускати
скопійовані розсилки й інші планові завдання. Доступи підключення Укркар налаштовуються
для локальної копії окремо. Для роботи лише його черги:

```sh
npm run dev -- --hostname 127.0.0.1 --port 3014
npm run dev:ukrcar-worker
```

Локальний worker відмовляється працювати з віддаленою базою або без вимкнення
загальних планових завдань. У production використовується штатний cron інтеграцій;
додатковий worker не потрібний.

## Перевірка

- Unit-тести: HTML, CSRF/cookies, пагінація, межі дат, точні суми, відсутні назви,
  заборонені перенаправлення, часткові помилки та відновлення лічильників.
- PostgreSQL-тести включені в `npm run test:finance`: конкурентний імпорт,
  ручні дублі з іншою датою, атомарність, ізоляція організацій і повторні натискання.
- Ручна перевірка: натиснути кнопку, дочекатися завершення, повторити;
  другий запуск має створити нуль чернеток за незмінного списку постачальника.

Інтеграція залежить від HTML кабінету Укркар. Зміни розмітки або способу входу
можуть потребувати оновлення адаптера.
